# R02: дополнение по сборке WPILib

Для новой физической модели: из `software` выполнить `mvn -Pwpilib clean verify`, затем `run-wpilib.cmd --desktop` (Windows) или `./run-wpilib.sh --desktop` (Linux). Нужны JDK 21, Maven 3.9+ и сетевой доступ к зависимостям. Этот маршрут в среде подготовки НЕ выполнен.

`software/dist/ubor-sim.jar` — действительно собранный старый backend LEGACY_FIRST_ORDER, НЕ WPILib. `build-offline` не компилирует WPILib. Полная новая инструкция — `README_RU.md` и `docs/25_WPILIB_R02.md`.

Исходный раздел ниже относится к R01. Архивные результаты перенесены в `verification/r01_archive/`. Генераторы R01 не создают новую главу WPILib; для неё предназначен `tools/render_wpilib_docs.py`.

# Воспроизводимая сборка комплекта

Готовые STEP, PDF и исполняемый симулятор уже находятся в архиве. Для просмотра этих файлов не нужно запускать генераторы.

## Java

Симулятор и пульт: JDK 21; Linux `software/build-offline.sh`, Windows `software/build-offline.ps1`. Сборка этих двух модулей не загружает сторонние зависимости.

Полный набор модулей: JDK 21, Maven, доступ к репозиторию зависимостей. Из каталога `software`: `mvn -Pfull clean install`, затем `bash assemble-full.sh`. Этот маршрут предусмотрен, но здесь не выполнялся. Не воспринимать наличие POM как доказательство совместимости нативного backend на Raspberry Pi. Начать целевую проверку с главы 19 книги и ML Preflight, не включая силовую часть.

## CAD и документы

Инструменты генерации работают на компьютере разработчика, не на роботе. Собственное бортовое ПО остаётся Java. Зафиксированные версии Python-пакетов находятся в `tools/requirements-cad-docs.txt`. Для CadQuery/VTK требуются совместимые нативные библиотеки и платформа; для PDF — системный пакет шрифтов DejaVu. Файлы шрифтов в архив не включены.

Из корня проекта, после установки необходимых зависимостей в отдельное окружение:

```sh
python cad/src/build_robot.py
python cad/src/render_cad.py
python tools/check_step.py
python tools/build_electronics.py
python tools/build_documents.py
```

`build_robot.py` создаёт геометрию, STEP деталей и сборок, BOM, расчётные параметры и ортогональные SVG. Рендер использует сохранённую CAD-сцену. `export_views.py` можно запускать отдельно для восстановления SVG из основного STEP. `build_electronics.py` создаёт граф соединений и KiCad-файлы; установленный KiCad этим скриптом не запускается. `build_documents.py` собирает книгу и PDF-комплекты из Markdown, CAD и графа соединений.

Исходная проверочная среда — Linux x86_64; сведения в `verification/r01_archive/environment.json`. Запуск этих генераторов на Windows или иной платформе здесь не проверялся. Экспорт CAD в STEP не переносит дерево параметрических операций CadQuery в SolidWorks: правки с полной историей нужно вносить в исходник, либо заново создавать операции в целевой CAD.

При изменении конфигурации, кода, схемы или геометрии нужно заново выполнить соответствующие проверки, обновить отчёт и контрольные суммы. Результаты этой ревизии автоматически на изменённый вариант не распространяются.
