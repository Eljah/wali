# UBOR-JAVA R01 — робот-сборщик мусора

Инженерный proof of concept от 23.09.2026. Механика CAD, электронная схема,
Java-управление, симулятор, пульт и исходники обучения двух DL4J-моделей.
**Не производственный комплект, не испытанный физический робот.**

## Начать здесь

На компьютере с Java 21, из каталога `software`:

```sh
java -jar dist/ubor-sim.jar --desktop
java -jar dist/ubor-sim.jar --demo ../verification/my-demo 90
java -jar dist/ubor-sim.jar --self-test ../verification/my-tests
```

В пульте нажмите `Arm / Disarm`, затем удерживайте SPACE. W/S/A/D или стрелки —
движение. C — подбор с выбранной человеком меткой. AUTO — модельный автономный
режим; в симуляторе используется **SIM_ORACLE_NOT_ML**, а не нейросеть.
Отпускание SPACE / потеря фокуса / потеря связи прекращают движение.
Для автоматического демонстрационного прогона используйте `--demo`.

Сборка без Интернета: `bash build-offline.sh` (Linux) или
`powershell -File build-offline.ps1` (Windows). Нужен JDK 21, не JRE.
Maven: `mvn clean verify`; полный проект с аппаратными/ML-зависимостями:
`mvn -Pfull clean install` и `bash assemble-full.sh`.
**Полная Maven-сборка здесь не выполнена: Maven/загрузка зависимостей недоступны.**
Исходники `robot-pi` и `robot-ml` не выдаются за прошедшие компиляцию или испытания.

## Реально проверено

Офлайн-компиляция Java 21 core/app, 50 проверок, реальный TCP loopback:
40 HMAC-команд и телеметрия, остановка после обрыва. Модельный прогон:
3 разрешённых предмета собраны, опасный объект оставлен. Проверены 121 валидное
тело и обратное чтение STEP. Для электроники выполнены структурные проверки
141 компонента / 100 цепей, но **не ERC, SPICE, запуск KiCad или испытание платы**.

Не выполнены: DL4J-обучение на фотографиях, ARM/native preflight, реальное GPIO/SPI,
испытание моторов/камеры, пространственная контактная физика мусора, проверка
схемы в KiCad, PCB, сертификация. Весов нейросетей нет; `models/README_RU.md`.

## Что это за робот

Около 810 × 545 × 665 мм, расчётная полная масса 30 кг, 4 кг груза,
24,12 л геометрического внутреннего объёма. Два ведущих колеса Ø200 мм,
две передние опоры, щётка и наклонный транспортёр шириной 320 мм. Один бункер;
классификация определяет допуск к сбору, **раздельной сортировки по контейнерам нет**.
Только сухой безопасный мусор на закрытом ровном полигоне при непосредственном
наблюдении оператора. Не тротуары с прохожими, не дороги, не мокрый мусор и не
опасные отходы. Номинальные расчёты — не измеренные характеристики.

## Аппаратный запуск закрыт по умолчанию

`calibration.complete=false`, неизвестные знаки моторов/энкодеров, пустая таблица
дальномера и отсутствие одобренных моделей не позволяют выдать штатный аппаратный
AUTO за готовый. До обучения предусмотрен `--hardware-teleop` с камерой и без ML.
Не обходите блокировки изменением флага без измерений и проверки.

Силовая часть требует инженерной доработки защиты от рекуперации и проверки
теплового режима. Подробности и порядок стендовых работ — в книге, главы 7–10, 21–24.
Java/ОС не являются сертифицированным контуром безопасности: физический аварийный
останов, внешний watchdog, ручной фронтовый повторный пуск и разрыв питания
приводов предусмотрены отдельно. Работы с питанием/механикой выполняются на
ограждённом стенде специалистом, при заблокированных приводах.

Весь собственный бортовой/пультовый/ML-код — Java. Python используется только для
генерации CAD, ECAD и документов; Java вызывает нативные библиотеки Pi4J/ND4J/OpenCV.
Готовые покупные микросхемы не требуют нашей микроконтроллерной прошивки.
